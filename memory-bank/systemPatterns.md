# System Patterns

## High-Level Architecture

The app supports two fully independent detection pipelines, selected at build time via `DETECTOR_BACKEND`. They share only the outer shell (routing, home screen, navigation service).

```
┌─────────────────────────────────────────────────────┐
│                     main.dart                        │
│  reads DETECTOR_BACKEND env var at startup           │
│  initialises selected backend only                   │
└──────────────┬──────────────────┬───────────────────┘
               │ tflite           │ yolo
               ▼                  ▼
   ┌─────────────────┐   ┌──────────────────────┐
   │  TensorflowSvc  │   │   ultralytics_yolo    │
   │  (SSD MobileNet)│   │   (YOLO11n)           │
   │  Singleton      │   │   Platform-native     │
   └────────┬────────┘   └──────────┬───────────┘
            │                       │
            ▼                       ▼
   ┌─────────────────┐   ┌──────────────────────┐
   │  Detector       │   │  YOLOView widget      │
   │  (Isolate)      │   │  (self-contained)     │
   └────────┬────────┘   └──────────┬───────────┘
            │                       │
            ▼                       ▼
   ┌─────────────────┐   ┌──────────────────────┐
   │  BoxWidget      │   │  onResult callback    │
   │  overlays on    │   │  (currently only      │
   │  CameraPreview  │   │   logging count)      │
   └─────────────────┘   └──────────────────────┘
```

## Design Patterns Used

### 1. Singleton — Services
`TensorflowService`, `NavigationService`, and `SnackBarService` are all implemented as Dart singletons using a private named constructor pattern:
```dart
static const ssdMobileNet = TensorflowService._(
  modelPath: AppConstants.ssdMobileNetV1,
  labelPath: AppConstants.ssdMobileNetV1LabelPath,
);
```
This ensures the TFLite interpreter is loaded exactly once and reused across the app lifetime.

### 2. Background Isolate — TFLite Inference
The SSD MobileNet path runs inference on a **separate Dart isolate** to avoid blocking the UI thread. This is the correct Flutter pattern for CPU-intensive operations:
```
UI Thread                     Background Isolate
─────────────                 ──────────────────
CameraImage frame  ──SendPort──▶  _DetectorServer
                               ├── converts YUV→RGB
                               ├── runs TFLite inference
                               └── streams DetectedObjectDm ──▶ UI
```
The `Detector` class owns the isolate lifecycle. On disposal, the isolate is killed and the stream is closed.

### 3. MobX Reactive Store — Home Screen
The home screen uses MobX for state management:
- `HomeScreenStore` holds `@observable` fields: `photos`, `unsplashPhotosState`, `paginatedState`
- `@action` methods: `searchPhotos()`, `fetchMore()`
- The UI reacts via `Observer` widgets from `flutter_mobx`
- Pagination is handled by scroll detection triggering `fetchMore()`

### 4. Retrofit + Dio — API Layer
The Unsplash API client is defined declaratively using Retrofit annotations:
```dart
@RestApi(baseUrl: 'https://api.unsplash.com')
abstract class ApiServiceType {
  @GET('/search/photos')
  Future<PaginatedResDm> searchPhotos({@Query('query') required String search});
}
```
Implementation is generated by `retrofit_generator` at build time. Dio is the underlying HTTP client.

### 5. JSON Serialization — Data Models
All API response models (`*_dm.dart`) use `json_serializable` annotations:
```dart
@JsonSerializable(fieldRename: FieldRename.snake)
class CreateSessionDm { ... }
```
All models use `FieldRename.snake` for automatic camelCase ↔ snake_case mapping. Serialization code is generated into `*.g.dart` files.

### 6. Enum-Driven Backend Config — DetectorConfig
The active backend is expressed as an enum throughout the codebase:
```dart
enum DetectorBackend { tflite, yolo, mlkit }
```
`DetectorConfig.backend` reads the compile-time environment variable and returns the appropriate enum value. All conditional branching in the app (initState, build methods) checks `DetectorConfig.backend`. `mlkit` is defined but not implemented.

### 7. Platform-Aware Model Loading — YOLO Path
The YOLO model path is resolved differently per platform at the widget level:
```dart
modelPath: Platform.isIOS ? 'yolo11n' : 'yolo11n.tflite'
```
- iOS: `'yolo11n'` → `ultralytics_yolo` loads this as a Core ML mlpackage from the Xcode bundle
- Android: `'yolo11n.tflite'` → package loads from `android/app/src/main/assets/`

## Data Flow: YOLO Live Detection (Primary Path)

```
Physical camera hardware
        │
        ▼
  YOLOView widget (ultralytics_yolo)
  ├── manages camera session internally
  ├── feeds frames to YOLO11n model
  │     ├── Android: TFLite runtime
  │     └── iOS: Core ML runtime
  ├── runs inference per frame
  └── fires onResult(List<DetectionResult>)
            │
            ▼
      onResult callback in LiveObjectDetectionScreen
      └── currently: log('YOLO results: ${results.length}')
              (no bounding box rendering yet in YOLO mode)
```

## Data Flow: TFLite Live Detection (Fallback Path)

```
camera plugin → CameraController
        │
        ▼ (stream of CameraImage frames)
Detector.resultsStream
        │
        ▼ (via SendPort to isolate)
_DetectorServer (background isolate)
  ├── ImageUtils.convertCameraImage() → img.Image (RGB)
  │     handles: YUV420, BGRA8888, JPEG, NV21
  ├── TensorflowHelper.analyseImage()
  │     ├── resize to 300×300
  │     ├── build [1,300,300,3] input tensor
  │     ├── interpreter.runForMultipleInputs()
  │     └── parse 4 outputs:
  │           locations [1,10,4] → bbox coords
  │           classes   [1,10]   → class indices
  │           scores    [1,10]   → confidence
  │           numDetections [1]  → count
  └── filter score > 0.5 → List<DetectedObjectDm>
            │
            ▼ (via ReceivePort back to UI)
LiveObjectDetectionScreen
  └── Stack of BoxWidget overlays on CameraPreview
```

## Data Flow: Static Image Analysis

```
User taps Unsplash photo or picks from gallery
        │
        ▼
HomeScreen downloads image bytes (NetworkAssetBundle / image_picker)
        │
        ▼
Navigate to PhotoAnalyzeScreen with imageBytes
        │
        ▼
TensorflowService.ssdMobileNet.analyseImage(Uint8List)
  (same TFLite pipeline as above but single-shot, not streaming)
        │
        ▼
PhotoAnalyzeScreen renders:
  ├── Image with drawn bounding boxes (TensorflowHelper.drawBoxes)
  └── ListView of DetectedObjectTile (label + score)
```

## Screen / Navigation Structure

```
Routes (lib/values/app_routes.dart):
  '/'         → HomeScreen
  '/detail/'  → PhotoAnalyzeScreen
  '/camera/'  → LiveObjectDetectionScreen

NavigationService (singleton) wraps Navigator for programmatic routing.
```

## Orientation Strategy
| Screen | TFLite Mode | YOLO Mode |
|---|---|---|
| HomeScreen | Portrait only | Portrait only |
| LiveObjectDetectionScreen | Portrait + Landscape | Landscape only (forced in initState) |
| PhotoAnalyzeScreen | Portrait + Landscape | Portrait + Landscape |

YOLO mode forces landscape in `initState` and restores portrait+landscape on `dispose`.
